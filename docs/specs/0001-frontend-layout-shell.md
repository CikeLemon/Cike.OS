# Spec: 前端 layout 层（管理端应用外壳）

> Triage: `ready-for-agent`
> 术语遵循根 `CONTEXT.md`：**管理端（Admin Console）**= 前端唯一应用外壳；**模块（Module）**= 侧栏一级导航单元。

## Problem Statement

前端目前是脚手架状态：单页入口、无路由、无布局，任何功能模块都没有可挂载的结构。用户（产品的操作者）无从进入对话、Agent、模型、工具等各模块；开发者每加一个功能都要重新发明一遍页面外壳，导航、主题、标题等全局行为没有归属。

## Solution

为管理端建立唯一的应用外壳：**inset sidebar 布局**（侧栏整列全高 + 内容区自带头部条）作为默认布局，以 vue-router 为骨架，路由表是导航与标题的单一来源。第一版交付完整外壳 + 六个模块的占位页；各模块的界面内容、权限、对话界面形态等由后续提案填充。

## User Stories

1. 作为产品操作者，我打开站点根路径就能直接进入对话模块，以便不经过任何中间页开始使用核心功能。
2. 作为产品操作者，我能在左侧整列侧栏中看到全部模块入口（对话、Agent、模型、工具、标签、设置），以便随时切换工作上下文。
3. 作为产品操作者，我点击侧栏导航切换模块时页面不整页刷新，以便保持流畅的切换体验。
4. 作为产品操作者，我能在侧栏中一眼看出当前所在的模块（高亮态），以便在大导航中不迷失。
5. 作为产品操作者，我能在内容区顶部看到当前模块的标题，以便确认当前工作对象。
6. 作为产品操作者，我切换模块后浏览器标签页标题同步更新为「模块名 · Cike.OS」，以便在多标签页间辨认。
7. 作为产品操作者，我能折叠侧栏获得更宽的工作区，以便在窄屏幕或专注场景下工作。
8. 作为产品操作者，我能用 Ctrl+B 快捷键切换侧栏折叠状态，以便双手不离键盘。
9. 作为产品操作者，我刷新页面后侧栏保持我上次选择的折叠/展开状态，以便不必重复调整。
10. 作为产品操作者，侧栏折叠成图标栏时我能通过悬停提示（tooltip）识别每个图标对应的模块，以便折叠态仍可导航。
11. 作为产品操作者，我在侧栏顶部看到「Cike.OS」字标、折叠时缩为首字母方标，以便在任何宽度下都保有产品身份感。
12. 作为产品操作者，我能一键切换亮色/暗色主题，以便适配环境光与个人偏好。
13. 作为产品操作者，我的主题选择被持久化，下次访问保持，以便不必每次重选。
14. 作为产品操作者，我首次访问时主题自动跟随系统偏好，以便零配置获得合理外观。
15. 作为产品操作者，我输入不存在的路径时看到 404 占位页而不是空白或报错，以便知道发生了什么并能返回。
16. 作为产品操作者，我能直接在地址栏输入模块路径深链进入对应模块，以便收藏和分享常用位置。
17. 作为产品操作者，未使用的模块页面按需加载，以便首屏保持轻快。
18. 作为开发者，我新增一个模块只需在路由表加一条带 title 与 nav 标志的记录，侧栏入口与标题即自动出现，以便导航永不与路由漂移。
19. 作为开发者，我能为特定路由指定不同于默认的布局，以便将来对话界面等沉浸式形态不被迫套用管理布局。
20. 作为开发者，我折叠/展开侧栏时操作按钮（内容头部左缘）位置恒定，以便交互心智稳定、不因状态切换而「搬家」。
21. 作为开发者，主题与颜色全部走语义令牌且暗色双值齐备，以便暗色模式是一等公民、无硬编码色失真。
22. 作为维护者，侧栏底部预留了空的 footer 槽位，以便将来用户菜单随权限提案落地时直接填充而不动骨架。
23. 作为维护者，「路由表 → 导航项」的推导逻辑有单元测试守护，以便重构路由结构时不静默破坏导航。
24. 作为维护者，布局层职责单一（外壳），页面内容一律在页面侧实现，以便外壳与内容各自独立演进。

## Implementation Decisions

- **骨架依赖**：引入 vue-router 作为唯一新增运行时依赖；应用入口退化为纯路由出口，脚手架遗留示例一并移除。
- **布局模式**：inset sidebar——侧栏从视口顶贯穿到视口底，与内容区并列；内容区顶部自带头部条。不设横贯全宽的顶栏。
- **侧栏结构**：三区——顶部为「Cike.OS」排版字标（折叠缩为「C」首字母方标，不引入图片资产）；中部为模块导航；底部为空 footer 槽位（将来用户菜单）。
- **内容头部条**：左缘为侧栏折叠按钮（跟随头部条，位置恒定）；中部为当前模块标题；右缘为主题切换按钮。模块标题来自路由 meta 的 title 字段，为标题的单一来源（顶条不做动态文案）。
- **折叠行为**：整列收缩为 48px 图标栏 + 悬停 tooltip，Ctrl+B 快捷键，状态 cookie 持久化——全部采用 shadcn-vue Sidebar 原生能力，不自研。
- **导航单一来源**：路由表为唯一事实来源，meta 携带 title 与 nav 标志；导航数组由路由表经纯函数推导生成，不手写第二份数组。新增模块只改路由表。
- **模块与路径**：一级菜单六个模块——对话、Agent、模型、工具、标签、设置；路径用英文复数（如 conversations）。根路径重定向到对话模块。用户工具配置归入设置，不单独占一级菜单。
- **404**：catch-all 路由指向占位页。
- **主题**：两态（light / dark），初始跟随系统偏好，手动切换后持久化到本地存储；主题取值用 const 对象 + 字面量联合类型表达（项目禁用 enum 语法）。
- **多布局注册体系**：路由可指定布局，未指定走默认布局；第一版只实现默认的 ConsoleLayout，不预建其它布局文件。
- **样式纪律**：全用语义令牌（侧栏令牌、前景/背景令牌等），zinc 中性色板，任何自定义颜色变量必须亮暗双值。
- **加载策略**：页面组件懒加载；布局组件同步加载。
- **响应式**：桌面优先，不做移动端专门适配，仅继承 Sidebar 组件自带的移动端抽屉行为。
- **占位页**：六个模块各一页，仅标题一行级别，内容等后续提案。

## Testing Decisions

- **原则**：只测外部行为（推导函数的输出形状），不测实现细节（不测内部如何遍历路由表）。
- **唯一自动化接缝**：「路由表 → 导航数组」纯函数推导。测试覆盖：nav 标志的项按声明顺序进入导航、非导航路由（重定向、404）被排除、title 正确传递、折叠无关。经用户批准，为此引入 vitest——这是前端首个测试设施，测试文件本身即先例（此前无 prior art）。
- **其余验收手动走查**：路由跳转与高亮、根路径重定向、折叠与持久化、快捷键、主题切换与持久化、标签页标题、404、深链、懒加载——按用户故事逐条在开发服务器中人工核验。

## Out of Scope

- 各模块页面的界面内容（含对话界面的具体形态）——后续单独提案。
- 登录、权限、路由守卫——后续单独提案；本次不留任何占位（不加 requiresAuth、不加守卫钩子）。
- 面包屑（当前无二级页面，无层级可显示）。
- 其它布局（沉浸全幅等）的实现——注册机制就位后按需追加。
- 移动端专门适配。
- 正式品牌 logo 资产——先用排版字标。
- 通知、用户菜单等 footer 槽位的填充。
