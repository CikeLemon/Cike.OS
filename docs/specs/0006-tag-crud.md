# Spec: 标签增删改查（含列表页排序与时间列统一）

> Triage: `ready-for-agent`
> 术语遵循根 `CONTEXT.md`（标签、键、名称、模型）；业务键唯一性由应用层承担、索引非唯一见 `docs/adr/0001-非唯一索引与软删共存.md`；标签的平台级定位见 ADR 0004。
> 2026-11-27 经设计访谈逐条定稿；此前一轮标签实现已被整体回退，不作为参考。

## Problem Statement

标签目前只能在数据库里有、界面上没有：侧栏有「标签」入口，点进去是占位页；后端只有一个只读的全量列表给模型表单当多选项。管理者想新增一个标签、改个名称、或者删掉一个不再用的标签，没有任何入口。

另外两张已有的列表页（模型、工具包）默认排序各不相同（一个按显示名称、一个按创建时间），而且都不显示创建时间和更新时间，看不出条目是什么时候建的、最近有没有改过。

## Solution

给标签补齐新建、编辑、删除、分页列表四条用例和一个管理页。标签只有两个字段：键是机器标识，创建后不变、全局唯一；名称给人看，可以改、允许重名。删除不做任何守护——被模型引用着也直接删，模型侧读取时把已经不存在的标签当作不存在处理。

顺带把全项目的列表页统一：分页列表默认按更新时间倒序，实体列表页一律显示创建时间与更新时间两列。

## User Stories

1. 作为管理者，我在侧栏点「标签」进入标签管理页，看到全部标签的分页列表，以便了解平台现有哪些标签。
2. 作为管理者，我点「新建标签」，填键和名称后保存，以便给模型多出一个可选项。
3. 作为管理者，我新建时键留空、或含大写字母、或以数字开头、或含非法字符，会被拒绝并看到提示，以便键始终是规整的机器标识。
4. 作为管理者，我新建时名称留空会被拒绝，以便每个标签都有可读的显示名。
5. 作为管理者，我新建时键与现有标签重复会被拒绝，以便一个键只指认一个标签。
6. 作为管理者，我删除一个标签后可以用同样的键重新建一个，以便软删的历史不挡路。
7. 作为管理者，我编辑标签时只能改名称、键是只读的，以便已经指认这个键的地方不会失效。
8. 作为管理者，我编辑保存后列表里名称立刻更新，以便确认修改生效。
9. 作为管理者，我删除标签时先看到确认框，确认后标签从列表消失，以便避免误删。
10. 作为管理者，我删除一个正被模型引用的标签不会被拦，以便清理不需要的标签时不用先去逐个解绑模型。
11. 作为管理者，我删掉标签后，模型列表里不再显示这个标签，以便界面上不出现指向不存在标签的「未知标签」。
12. 作为管理者，我编辑一个曾引用已删标签的模型，编辑框只勾选仍然存在的标签，保存后模型上不再残留已删标签的引用，以便模型能正常保存。
13. 作为管理者，我在搜索框输入关键字回车，列表只显示键或名称包含该关键字的标签，以便快速定位。
14. 作为管理者，我不输入关键字时，列表默认最近更新的排在最前，以便先看到刚动过的标签。
15. 作为管理者，标签列表为空时我看到的空态文案会区分「还没有任何标签」和「没有符合条件的标签」，以便判断是该新建还是该改搜索词。
16. 作为管理者，标签列表每一行都显示创建时间和更新时间，以便知道这个标签何时建立、最近何时改过。
17. 作为管理者，模型列表、工具包列表同样默认按更新时间倒序排列，以便各模块行为一致。
18. 作为管理者，模型列表、工具包列表、模型提供方列表都同时显示创建时间和更新时间，以便不进详情就能看到时间信息。
19. 作为管理者，在接入点表单里选模型的下拉仍然按模型名称排序，以便按名字找模型。
20. 作为管理者，保存失败时（键重复、校验不通过）我在页面上看到中文错误提示，对话框不关闭，以便修改后重试。
21. 作为前端开发者，我执行 `pnpm gen:api` 后拿到的函数覆盖标签的全部端点，以便不手写 URL。
22. 作为后端开发者，标签实体遵循项目的 DDD 约定（私有 set、静态工厂、意图方法，实体内不写单字段校验），以便与模型、提供方等聚合保持同一风格。
23. 作为后端开发者，键的唯一性由用例层先查再写承担、数据库不加唯一索引，以便与软删共存（沿 ADR 0001）。
24. 作为未来的实现 agent，我拿到本 spec 即可独立完成全部实现（决策均已定稿），不必再做架构裁决。

## Implementation Decisions

### 后端

- **实体**（`Tag`，平台级聚合根，无租户）：收口为严格 DDD——属性 `private set`、私有无参构造、静态工厂 `Create(key, name)`、意图方法 `Rename(name)`。实体 / 工厂 / 意图方法内不写任何单字段基础校验（非空、长度、格式全部在 FluentValidation）。键没有修改方法，创建后不可变由类型本身保证。
- **DTO**（Application.Contracts，`Tags/Dtos`）：
  - 输入 `CreateTagDto`：`Key`、`Name`。输入 `UpdateTagDto`：只有 `Name`（键不可变，不进更新体）。
  - 查询 `GetTagPagedListQuery(string? Keyword, PagedAndSortedResultRequest Paging)`：分页参数用框架的 `PagedAndSortedResultRequest` 对象承载，只有一个筛选字段所以平铺、不另建继承它的 Dto（实现时按框架「Dto 编写约定」修正，见 Backend AGENTS.md）。
  - 输出沿用现有 `TagDto`（Id、Key、Name + 审计字段）作为分页行与全量列表项。标签没有子实体、字段就是这三样，不另建列表 DTO（与模型分页列表复用 `ModelDto` 的先例一致）。
- **用例**（Application，`Tags/`）：`CreateTagCommand(Dto)`（回填 Id）、`UpdateTagCommand(Id, Dto)`、`DeleteTagCommand(Id)`、`GetTagPagedListQuery(string? Keyword, PagedAndSortedResultRequest Paging)`（结果 `PagedResultDto<TagDto>`）。现有 `GetTagListQuery` 保留不动。
- **Handler**：
  - 创建：先查键是否已存在（`GetCountAsync` 下推，软删过滤生效故已删的同键不算重复），命中抛「键「{key}」已存在。」；再调工厂、插入。只有创建有跨聚合校验，更新没有，因此不建共用的 `ValidateAsync`。
  - 更新：加载标签（不存在抛「标签不存在」），调 `Rename`，保存。
  - 删除：加载标签，直接删除（框架软删）。**不检查模型引用，不改任何模型数据。**
  - 分页查询：`BeginAsNoTracking`；`Keyword` 非空时谓词为「键包含 或 名称包含」；`GetPagedListAsync(dto, predicate)` 直接透传，排序由前端传入的 Dynamic LINQ 字符串决定，后端不写默认排序；实体 → DTO 走 Mapster `Adapt`。
- **端点**（Service.Open 的 `TagService`，约定路由，与 `ModelService` 同形）：`GET /api/v1/Tags/PagedList`（`[AsParameters]` 接查询 DTO）、`POST /api/v1/Tags`（返回新 Id）、`PUT /api/v1/Tags/{id}`、`DELETE /api/v1/Tags/{id}`。现有 `GET /api/v1/Tags/List` 不动，继续供模型表单多选与模型列表回显名称。
- **Validator**（FluentValidation，`Tags/Validators`）：
  - `CreateTagDtoValidator`：`Key` 必填、匹配 `^[a-z][a-z0-9_-]*$`、≤ 64；`Name` 必填、≤ 128。
  - `UpdateTagDtoValidator`：`Name` 必填、≤ 128。
  - 不写 `Trim()`，body 字符串去空白由框架的 `TrimStringJsonConverter` 负责。
- **模型读侧**：模型分页列表查询在取到当前页之后，把页内全部模型引用的标签 Id 去重后**一次**批量查出仍然存在的 Id（`BeginAsNoTracking`、只投影 Id 列），再逐个模型过滤掉不存在的引用，然后 `Adapt` 成 DTO。只改分页列表；模型单个详情查询与模型写侧用例（含「标签必须存在」校验）都不动。
- **EF 与迁移**：零迁移、零表结构变更。键与名称的列长度已是 64 / 128，不给键加索引。
- **测试造数**：`TestDataFactory` 里直接 `new Tag` 写 DbContext 的造数方式在属性收私后不可用，改为发布创建用例造数。
- **不动的东西**：缓存层无人引用的 `TagCacheDto` 不删（范围外）；标签写端点不加角色鉴权（现有平台端点都没有，属全局议题）。

### 前端

- **路由**：`/tags` 已在路由表（标题「标签」、nav、图标），不改。
- **标签列表页**（替换占位页，照模型列表页的布局）：
  - 工具条：搜索框（占位「搜索键或名称，回车确认」）+「搜索」按钮 + 右侧「新建标签」。
  - 表格列：键（等宽字体）/ 名称 / 创建时间 / 更新时间 / 操作（编辑、删除）。时间用现有 `formatDateTime`。
  - 分页每页 10，请求固定传 `Sorting: 'UpdatedAt desc'`；关键字为空时不传 `Keyword`。
  - 空态：无筛选条件时「标签为空，点击右上角新建。」，有筛选条件时「没有符合条件的标签。」
  - 删除走现有 `DeleteConfirmDialog`，文案「确定删除标签「{名称}」？引用它的模型将不再显示该标签。」成功后刷新列表。
- **标签表单对话框**（新建 / 编辑共用一个居中 Dialog，不内联在页面里）：字段为键、名称；编辑态键禁用并提示「键创建后不可修改」；前端校验（键必填与格式、名称必填）由纯函数负责；保存成功 toast 并关闭，失败 toast 错误、对话框不关。
- **纯函数层**（vitest 接缝）：
  - 标签表单：表单状态 → 创建 / 更新请求体、前端校验（键正则与后端一致）。
  - 模型编辑框：从模型原有标签 Id 中保留当前标签列表里能匹配到的 Id（输入：模型的 Id 数组 + 标签数组；输出：过滤后的数组）。
- **模型列表页**：排序改传 `UpdatedAt desc`；新增「创建时间」「更新时间」两列（操作列前）；标签列只渲染能查到名称的 Id，删除「未知标签」兜底（后端已过滤，不会再出现）。
- **模型编辑框**：打开编辑时，表单里的标签 Id 经上述纯函数过滤后再回填；新建与提交逻辑不变。标签列表请求失败时（页面以 `tagsReady` 标记就绪）不过滤、禁止保存并提示刷新，避免把模型上的标签全部丢掉（code review 补）。
- **工具包列表页**：排序改传 `UpdatedAt desc`；新增「创建时间」「更新时间」两列。
- **模型提供方列表页**：新增「创建时间」列（已有「更新时间」列）。
- **不改**：接入点表单里选模型的下拉继续传 `DisplayName asc`；提供方详情里的接入点表、工具包详情里的工具表不加时间列。
- **API 层**：后端跑起后执行 `pnpm gen:api` 生成 `src/api`，组件只从 `@/api` 导入生成函数与类型。
- **组件引入**：全部复用已引入的 table / dialog / input / label / button / badge，不新增 shadcn 组件。
- **约定落盘**：「分页列表默认 `UpdatedAt desc`、实体列表页一律显示创建 / 更新时间两列」已写入前端 `AGENTS.md` 的「组件约定」。

## Testing Decisions

- **测试接缝**（全部沿用既有接缝，不新增）：
  - **后端主接缝**：从发布 Command / Query（经 `ILocalEventBus`）这一最高点进入，使用既有的 SQLite 内存测试宿主，只测外部行为（返回的 DTO、抛出的业务异常、随后查询到的状态），不测实体内部方法。先例 `ModelTests`。
  - **后端校验接缝**：FluentValidation 的 `TestValidate`。先例 `CreateModelDtoValidatorTests`。
  - **前端**：纯函数接缝（vitest）+ 浏览器走查兜底，不写组件测试。先例 `lib.test.ts` 与各模块表单纯函数测试。
- **好的测试**：只断言可观察行为——保存了什么、读出来是什么、什么被拒绝；不依赖实体私有方法名、不依赖 SQL。
- **后端用例清单**（新建 `TagTests`，挂在既有测试宿主上）：
  - 创建 → 分页列表与全量列表都能读到键、名称。
  - 键重复拒绝（报错可见）；软删后同键可重建成功。
  - 更新只改名称；键不可变（更新体没有键）；更新不存在的标签被拒。
  - 删除后两个列表都不再返回；删除不存在的标签被拒。
  - 删除被模型引用的标签**成功**，模型数据不被动。
  - 分页：按关键字命中键、命中名称、不命中返回空；平台级——任一租户下看到的标签一致。
- **校验用例**（`CreateTagDtoValidatorTests`、`UpdateTagDtoValidatorTests`）：键为空、大写、数字开头、含非法字符、超长各自有错；合法键（含 `-`、`_`、纯字母）通过；名称为空 / 超长有错。
- **模型读侧用例**（补进 `ModelTests`）：模型引用一个标签 → 删除该标签 → 模型分页列表里该模型的标签 Id 为空；仍存在的标签引用保留。既有的「提交不存在的标签 Id 被拒」用例保持通过（写侧语义未变）。
- **前端用例**：标签表单纯函数（合法 / 非法键、名称必填、创建与更新请求体形状、编辑态不带键）；模型编辑框过滤纯函数（保留能匹配的、丢弃匹配不到的、空输入）。
- **验收**：`dotnet build` 0 警告、`dotnet test` 全绿；`pnpm gen:api` 后 `pnpm build`（含 `vue-tsc`）与 `pnpm test` 通过；浏览器走查：新建标签（含一次非法键、一次重复键）→ 编辑名称 → 搜索 → 删除 → 到模型页确认该标签不再显示 → 编辑曾引用它的模型能正常保存；模型、工具包、提供方三个列表的时间列与默认顺序正确。

## Out of Scope

- 平台写端点的角色鉴权。
- 删除缓存层无人引用的 `TagCacheDto`。
- 模型表单里「输入新标签名即创建」的快捷建标签。
- 标签的批量创建 / 导入、排序字段（拖拽排序）、标签与模型之外其它资源的关联。
- 修改模型写侧「标签必须存在」的校验语义；模型单个详情查询的悬空引用过滤。
- 提供方详情里的接入点表、工具包详情里的工具表加时间列；接入点里选模型下拉的排序。

## Further Notes

- **发布通道**：本仓库的 issue tracker 与 triage 标签词表仍未配置（`docs/agents/` 不存在、本机无 gh CLI），本 spec 沿前例以仓库内 markdown 落盘并标注 `ready-for-agent`，tracker 就绪后再搬运。
- **悬空引用的取舍**：删除标签不清理模型上的引用，是用户明确选择的做法——残留的 Id 只在读取与再次保存时被当作不存在，数据库里允许暂时留有悬空 Id，不做对账。
- **术语已更新**：`CONTEXT.md` 的「标签」补上了键 / 名称分工与删除语义，实现时以此为准。
- **环境事实**：`.env.development` 的 `VITE_API_BASE_URL` 指向 https 端口，后端须以 `https` launch profile 启动；`pnpm gen:api` 的 swagger 来源是 http 端口。
- **验证链**：build + `dotnet test` + 抓 swagger + `pnpm gen:api` 后看 `src/api` diff + `pnpm build` 一趟过；SQLite 测试不能替代 MySQL 行为验证。
