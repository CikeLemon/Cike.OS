# Spec: 模型提供方即连接，模型为其子实体（删除接入点、映射与模型页面）

> Triage: `ready-for-agent`
> 术语遵循根 `CONTEXT.md`（模型提供方、模型、协议、标签）；结构决策见 `docs/adr/0007-模型提供方即连接模型为其子实体.md`（取代 ADR 0004 / 0005 / 0006）；聚合内子实体的写法、校验三层划分见 `Backend/AGENTS.md`；索引非唯一与软删共存见 ADR 0001；值对象直接作 API 契约见 ADR 0003。
> 本 spec 取代 spec 0004 / 0005 / 0007 / 0008 的全部内容——它们描述的接入点、提供商映射与平台级模型目录整体删除。2026-11-27 经设计访谈定稿；领域层的两个实体已由用户改定，是本 spec 的唯一标准，其余各层仍是被取代的旧结构。

## Problem Statement

现在的模型域有三层概念：平台级的「模型」目录、挂在提供方下的「接入点」、再把两者连起来的「提供商映射」。管理者想给智谱接上模型，要先在「模型」页面建目录条目，再建一个只有名称的提供方，进详情页建接入点，最后在接入点里逐条做映射；同一个模型想换一种协议再接一遍，整套流程要重来。这三层是围绕「同一个模型在多个供应商之间按分数路由」设计的，而这个需求并没有确定的来源。参照 zcode 的模型设置，管理者真正需要的只有两层：一个提供方填好地址、协议、密钥，下面列出它提供的模型。

## Solution

按 ADR 0007 收回两层：删除接入点、提供商映射与平台级模型目录。模型提供方就是一条连接——名称、一种协议、接入地址、密钥、协议专属设置；模型是它下面的条目——名称、描述、标签。同一家供应商有几种协议就建几个提供方。管理端只留「模型提供方」一个页面：列表加一个新建 / 编辑共用的表单对话框，连接字段和模型表在同一个表单里，一次保存。侧栏不再有「模型」，提供方也没有详情页。

## User Stories

1. 作为管理者，我在侧栏只看到「模型提供方」一个入口，看不到「模型」，以便不用理解「目录」和「映射」这两层概念。
2. 作为管理者，我点「新建模型提供方」打开一个表单，一次填好名称、协议、接入地址、API 密钥、协议专属字段和它提供的模型，以便一条连接一次配好。
3. 作为管理者，我可以在表单里不添加任何模型就保存，以便先立起连接、之后再补模型。
4. 作为管理者，表单下半部分是模型表（名称、标签、描述、操作），右上角有「添加模型」，以便一眼看出这个提供方提供哪些模型。
5. 作为管理者，我点「添加模型」或某一行的铅笔时打开一个小对话框填名称、描述、标签，确定后回到模型表，以便描述和标签多选不把表格撑乱。
6. 作为管理者，我在小对话框里点确定只是把这条模型留在表单里，要点表单的「保存」才真正提交，以便中途取消不留半截数据。
7. 作为管理者，编辑已有模型时名称是只读的，只能改描述和标签，以便模型名称（调用时原样发给提供方）不会被误改。
8. 作为管理者，我添加一个名称与表单里已有模型相同的模型时被前端拦下，以便一个提供方下同一个模型名只出现一次。
9. 作为管理者，我提交的模型列表里有重名时被后端拒绝且什么都不保存，以便绕过前端也不会存进重复的模型。
10. 作为管理者，我可以点模型行上的删除把它从表单里移除，保存后这条模型不再属于该提供方。
11. 作为管理者，我点列表里的「编辑」时，表单里是这个提供方此刻最新的连接信息和全部模型，以便别人刚改过的内容不会被我的旧页面覆盖。
12. 作为管理者，我编辑时可以修改协议，修改后协议专属字段区切换成新协议的字段，以便换协议不用删掉提供方重建、丢掉名下全部模型。
13. 作为管理者，我切换协议时如果专属字段已有输入，先看到确认提示，确认后才清空，以便不悄悄丢掉刚填的内容。
14. 作为管理者，我提交的协议与协议专属设置的类型对不上时被拒绝且什么都不保存，以便存下来的设置与协议一致。
15. 作为管理者，我不填 OpenAI 的组织标识、不填 Anthropic 的 API 版本也能保存。
16. 作为管理者，我在同一个租户下用已存在的名称新建或改名提供方时被拒绝，以便同租户的提供方可以按名称区分。
17. 作为管理者，不同租户可以用相同的提供方名称，也可以各自有同名的模型。
18. 作为管理者，我给智谱的 OpenAI 兼容端点和 Anthropic 兼容端点各建一个提供方，两个提供方下都可以有 `glm-5.3`，它们互不影响。
19. 作为管理者，我给模型选了已被删除的标签、或提交了不存在的标签时被拒绝且什么都不保存，以便模型永远只指向真实存在的标签。
20. 作为管理者，我打开一个引用了已删标签的提供方来编辑时，表单里不会出现那条已删标签，保存也不会因为它的残留引用被拦下。
21. 作为管理者，我删除一个提供方时看到「名下全部模型会一并删除」的确认提示，确认后提供方和它的模型一起消失。
22. 作为管理者，我看不到别的租户的提供方和模型，按别的租户的 Id 取详情得到「不存在」。
23. 作为管理者，列表里每个提供方一行，显示名称、协议、它提供的模型名称、创建时间、更新时间，以便不打开表单就知道概况。
24. 作为管理者，我访问 `/models` 或 `/model-providers/{id}` 时落到「页面未找到」，以便旧地址不留死角。
25. 作为前端开发者，我执行 `pnpm gen:api` 后拿到的函数里不再有接入点与模型目录的端点，提供方的五个端点请求体带连接字段与模型列表，组件只从生成层导入、不手写 URL。
26. 作为后端开发者，模型提供方是租户级聚合根，模型是它聚合内的子实体，随提供方的请求整体同步、没有独立的用例、DTO 入口和路由，以便聚合形状与它的生命周期一致。
27. 作为后端开发者，模型同步以名称为键——提交的条目不带 Id，名称已存在的更新描述与标签、不存在的新增、没提交的删除，以便「名称创建后不可变」由同步方式本身保证、不用额外断言。
28. 作为后端开发者，更新和删除提供方时连同模型集合加载（跟踪），被移除的模型才会跟着软删，以便级联删除不靠数据库行为。
29. 作为后端开发者，列表查询不加载聚合、只投影需要的列，详情查询连同模型一起加载后交给 Mapster，以便数据量上来后数据库不被整棵聚合拖垮。
30. 作为后端开发者，协议专属设置继续用多态值对象直接作为 API 契约与持久化形状，判别值不变，以便不建 DTO 镜像、存量 JSON 形状不变。
31. 作为后端开发者，协议专属设置的类型名叫 `ModelProviderSetting`（子类同样不含「Endpoint」），以便代码里不再出现已经不存在的概念。
32. 作为测试者，我能在不手写 URL 的情况下验证提供方五条路由的请求体（含多态设置）、校验失败与业务拒绝两种 400、详情的 404、租户隔离，以及已删除的路由不再存在。
33. 作为测试者，我能在实体映射冒烟测试里确认模型随提供方保存、从集合移除后软删、删提供方连带软删、一级预加载能把模型查全。
34. 作为未来的实现 agent，我拿到本 spec 即可独立完成全部实现（决策均已定稿），不必再做架构裁决。

## Implementation Decisions

### 后端

- **实体**（严格 DDD：聚合根 `private set` + 静态工厂 + 意图方法；实体 / 工厂 / 意图方法内不写单字段基础校验，只有赋值与集合内部不变量）：
  - `ModelProvider`（租户级聚合根，字段已由用户定稿）：`Name`、`Protocol`、`BaseUrl`、`ApiKey`、`Setting`（多态值对象）、`Models`（私有 set 的子实体集合）。补静态工厂 `Create(...)`（接收连接字段与初始模型列表）与两个意图方法：`Update(name, protocol, baseUrl, apiKey, setting)`——只赋值；`SyncModels(...)`——以名称为键整体同步，提交的条目里名称重复是聚合内部不变量，在此断言。协议专属设置的子类型与协议是否一致是输入校验，只在 FluentValidation（`ModelProviderSettingRules`），聚合里不断言。
  - `ModelEntity`（聚合内子实体，`FullAuditedEntity<long>` + `IMultiTenant`，字段已由用户定稿）：`ModelProviderId`、`Name`、`Description`、`TagIds`。意图方法 `internal`、工厂 `public`：`Create(name, description, tagIds)` 由 Handler 构造后交给 `ModelProvider.Create` / `SyncModels`（聚合根不收应用层的输入类型）；`Update(description, tagIds)` 只有聚合根能调——没有改名称的方法，名称创建后不可变由类型本身保证；标签引用去重是聚合内不变量。
  - 删除 `ModelProviderEndpoint`、`ModelProviderMapping` 两个实体（工作区里已删）。
- **值对象**（Domain.Shared，直接作为 API 契约，沿 ADR 0003）：`ModelProviderEndpointSetting` 族改名 `ModelProviderSetting`，子类改名 `OpenAIChatCompletionModelProviderSetting` / `AnthropicModelProviderSetting` / `OpenAIResponseModelProviderSetting`；字段（`Organization` / `Version`，可空）、判别键 `type` 与判别值（1 / 2 / 3）都不变。基类上仍不放「当前是哪个协议」的投影属性，判断子类型用类型模式匹配。枚举 `ModelProviderProtocol` 不动。
- **用例**（Application）：只剩 `ModelProviders/` 一套——`GetList`、`Get`、`Create`、`Update`、`Delete`。删除 `ModelProviderEndpoints/`、`Models/` 两套目录（Command / Query / Validator / Handler / DTO 全部）。标签用例不动。
  - `Create`：校验后调工厂，插入。
  - `Update`：连同 `Models` 一级预加载（跟踪）聚合，不存在抛「模型提供方不存在」（不区分「不属于本租户」）；校验后先 `Update` 连接字段、再 `SyncModels`，保存。
  - `Delete`：连同 `Models` 加载（跟踪）后删除聚合，模型随之软删。没有任何守护。
  - 跨聚合校验收敛为一个私有 `ValidateAsync`，创建 / 更新共用（`excludeId`）：提供方名称同租户唯一（一次计数）；全部模型引用的标签 Id 去重后一次计数核对是否都存在。标签是平台级实体，不需要关租户过滤器。被拒时什么都不保存。
  - `GetList`：不加载聚合，两次投影查询（提供方的名称 / 协议 / 创建与更新时间与操作人；模型的所属提供方 / 名称），全程不跟踪，内存里按提供方拼行，模型名称按名称排序。
  - `Get`：连同 `Models` 一级预加载、不跟踪，`Adapt` 成详情 DTO，模型按名称排序。
- **端点**（Service.Open）：只有 `ModelProviderService` 一个端点类，五条约定路由不变——`GET /ModelProviders/List`、`GET /ModelProviders/{id}`（不存在 404）、`POST`（返回新 Id，long 序列化为字符串）、`PUT /ModelProviders/{id}`、`DELETE /ModelProviders/{id}`。删除 `ModelProviderEndpointService` 与 `ModelService`。响应形状沿用现状：FluentValidation 失败 400 + ProblemDetails，业务拒绝 400 + 消息文本，取不到单条资源 404。
- **DTO**（Application.Contracts，`ModelProviders/Dtos/`）：
  - 输出 `ModelProviderDto`：继承审计基类（Id + 创建 / 更新时间与人）+ 名称、协议、接入地址、密钥、协议专属设置、`Models: List<ModelDto>`。
  - 子实体输出 `ModelDto`（从原 `Models/Dtos` 迁入）：继承审计基类 + 名称、描述、标签 Id 列表。
  - 模型输入 `SaveModelProviderModelDto`：名称、描述、标签 Id 列表——**不含 Id**（同步以名称为键）。
  - 输入 `CreateModelProviderDto` 与 `UpdateModelProviderDto` 字段相同：名称、协议、接入地址、密钥、协议专属设置、模型列表；更新 DTO 不含 Id（在路由）。协议可变，所以更新 DTO 含协议。
  - 列表专用 `ModelProviderListDto`：继承审计基类 + 名称、协议（单个）、模型名称列表。去掉原「协议列表 / 模型显示名称 / 接入点数」。
- **Validator**（FluentValidation，类级 `[AutoValidation]`；规则已逐条经用户确认）：
  - 提供方新建 / 更新（两个 Validator 规则相同）：名称必填 ≤ 128；协议必须是合法枚举值；接入地址必填、不校验 URL 格式；API 密钥必填、不限长度；协议专属设置必填且子类型必须与协议一致；模型列表不能为 null，可以是空列表；列表每一项挂模型项 Validator。
  - 模型项：名称必填 ≤ 128；描述可选 ≤ 2048；标签 Id 列表不能为 null，每项 > 0。
  - 协议专属设置的字段级规则沿用现有写法（迁入提供方的 Validator 目录并随类型改名）。
  - 不写 `Trim()`，body 字符串去空白由框架负责。
- **缓存层**：无人引用的 `ModelCacheDto` 去掉 `DisplayName`，与实体对齐。
- **EF 与数据**：
  - 实体映射：提供方补协议、接入地址、密钥、协议专属设置（json 列，沿用现有值转换器与 `JsonHelper`）；`HasMany(Models).WithOne().HasForeignKey(ModelProviderId).OnDelete(Cascade)`。模型映射补租户与所属提供方索引、去掉显示名称；`TagIds` 的 json 转换不变。删除接入点与映射两个配置类。全部索引非唯一（沿 ADR 0001）。
  - 在现有迁移之后**新增一个 EF 迁移**：删除接入点与映射两张表；提供方表加协议、接入地址、密钥、设置列；模型表加租户与所属提供方列（含外键）、去掉显示名称与并发戳列。
  - **应用该迁移前必须先硬删 dev 库里的模型、映射、接入点、提供方四张表的全部行（含已软删的）**：存量模型行是平台级目录、没有所属提供方，加非空外键时会失败。不写数据迁移。迁移只能由 `dotnet ef` 生成，不手改。
  - 生成迁移后先看内容：除上面列出的操作之外若有别的改表操作，停下来先报告再继续。
- **文档同步**：
  - `Backend/AGENTS.md`：以接入点 / 映射为先例的条款（多态值对象先例、Mapster 先例、平台级实体例外、聚合边界与子实体写法先例、一级预加载先例、HTTP 测试先例）全部改为现行事实——平台级实体只剩 `Tag`，子实体先例是 `ModelProvider → ModelEntity`，聚合边界的判据仍引 ADR 0006（它是历史来源，不再是现行结构）。
  - `Frontend/cike.os/AGENTS.md`：目录结构、测试说明、列表页时间列约定里涉及「模型页」「接入点」的表述改为现行事实。
  - spec 0004 / 0005 / 0007 / 0008 顶部各加一条「已被本 spec 取代」的修订注记，正文不动。

### 前端

- **路由与菜单**（nav 由路由 meta 推导）：删除 `/models`（「模型」）与 `/model-providers/:id`（详情页）两条路由；`/model-providers` 保留。侧栏变为七项：对话 / Agent / 模型提供方 / 工具包 / 工具包分类 / 标签 / 设置。
- **页面**：删除模型列表页与提供方详情页。`ModelProvidersPage` 保留：工具条（「新建模型提供方」）+ 表格（名称 / 协议徽标 / 模型名称徽标 / 创建时间 / 更新时间 / 操作：编辑、删除），本租户全量不分页。行不可点击跳转。
  - 点「编辑」：先按 Id 取详情，成功后才打开表单对话框；失败 toast 且不打开。
  - 删除确认文案：「确定删除模型提供方「{名称}」？名下全部模型会一并删除。」
- **表单对话框**（新建 / 编辑共用，宽度加大到能放下模型表；可滚动的表单容器是 grid 时加 `content-start`）：
  - 上半「连接」：名称、协议（下拉，编辑态可改）、接入地址、API 密钥、当前协议的专属字段（可空）。
  - 下半「模型」：表格（名称 / 标签徽标 / 描述截断 / 操作：编辑、移除）+ 右上角「添加模型」；为空时显示空态。
  - 切换协议：专属字段已有输入时先 `AlertDialog` 确认，确认后清空专属字段；名称、地址、密钥、模型表保留。
  - 「保存」提交整个表单；成功后 toast、关闭并刷新列表。
- **模型小对话框**（新建 / 编辑共用）：名称（新建可填、编辑只读并提示「创建后不可修改」）、描述 textarea、标签多选（沿用现有模型表单的多选做法，不为此引入新组件）。确定 = 前端校验通过后把这条写回表单的模型列表（同名且是新增 → 拦下「该模型已添加」）；不做任何请求。
- **纯函数层**（vitest 接缝）：表单状态 ↔ 新建 / 更新请求体、按协议组装协议专属设置、前端自身校验、模型条目的加入 / 替换 / 移除（以名称为键）、编辑回填时过滤掉已不存在的标签 Id（从原模型表单纯函数迁入）。标签列表未就绪时不过滤、模型小对话框不允许确认并提示刷新。
- **删除**：模型表单对话框及其纯函数、接入点抽屉及其纯函数与测试、提供方详情页相关的汇总纯函数。
- **API 层**：后端跑起后执行 `pnpm gen:api` 重新生成，组件只从生成层导入函数与类型，不手写 URL。
- **组件引入**：复用已引入的 table / dialog / alert-dialog / select / badge / input / label / textarea，不新增 shadcn 组件。

## Testing Decisions

- **测试接缝**（全部沿用现有接缝，不新增）：
  - **后端业务规则**：从发布 Command / Query（经 `ILocalEventBus`）这一最高点进入，使用既有 SQLite 内存测试宿主。先例 `ModelProviderTests`。
  - **后端校验**：FluentValidation 的 `TestValidate`。先例 `ModelProviderDtoValidatorTests`。
  - **HTTP 形状**：真实宿主 `ServiceOpenTestHost`。先例 `ModelProviderEndpointHttpTests`（该类改写为提供方路由的测试）。
  - **EF 行为**：既有实体映射冒烟测试。先例 `EntityConfigurationSmokeTests`。
  - **前端**：纯函数接缝（vitest）+ 浏览器走查兜底，不写组件测试。先例 `endpoint-form.test.ts`（改写为提供方表单纯函数测试）、`nav-items.test.ts`。
- **好的测试**：只断言可观察行为——保存后读出来是什么、什么被拒绝、HTTP 响应的状态码 / 内容类型 / 响应体形状；不断言实体私有方法、不依赖 SQL。
- **后端用例清单**（`ModelProviderTests` 重写）：
  - 创建：带连接与三个模型创建 → 详情返回连接字段（协议专属设置子类正确、未填时为 null）与按名称排序的模型；不带模型创建 → 详情模型列表为空。
  - 重名：同租户重名拒绝且不保存；跨租户同名放行；改名为兄弟的名称被拒；删掉后同名可重建。
  - 协议：更新后协议与专属设置子类一并改变；设置子类型与新协议不匹配被拒且不改任何东西。
  - 模型同步：更新时已存在名称的模型只改描述与标签、新增的追加、没提交的移除（读详情确认）；移除后提供方仍在；提交列表内重名被拒且什么都不保存；两个提供方下同名模型放行。
  - 标签：引用不存在的标签被拒且不保存（新建 / 更新各一次）；不存在的标签只出现在某一条模型里时整次提交被拒。
  - 级联：删提供方后详情为空。
  - 隔离：别的租户的提供方 Id 取详情为空、更新 / 删除按「模型提供方不存在」被拒。
  - 列表：按名称排序；每行的协议与模型名称正确。
- **校验用例**（`ModelProviderDtoValidatorTests` 重写）：名称为空 / 超长；协议为非法值；接入地址为空但不成 URL 的值放行；密钥为空；设置为 null、设置类型与协议不匹配；模型列表为 null、为空放行；模型名称为空 / 超长、描述超长、标签列表为 null、标签 Id 为 0。
- **HTTP 用例**（提供方五条路由）：动词与路径；新建返回字符串形式的 Id 且详情能按它取回；详情不存在 404；校验失败 400 + ProblemDetails；业务拒绝 400 + 消息文本；多态设置的请求体按 camelCase 判别键能正确反序列化并以同样形状返回；按租户头隔离；`/ModelProviderEndpoints` 与 `/Models` 下的路由不再存在。
- **EF 冒烟**：模型随提供方保存时自动生成雪花 Id、写入租户与外键；一级预加载能把提供方连同模型查全；从集合移除模型后保存即软删；删提供方连带模型软删。
- **前端用例**：路由表 nav 为七项、被删路由不存在；表单纯函数（表单转新建请求体含模型列表、转更新请求体含协议、按协议组装设置、未填专属字段为 null、前端校验）；模型条目的加入 / 替换 / 移除；编辑回填过滤已删标签。
- **验收**：`dotnet build` 0 警告（既有三条除外）、`dotnet test` 全绿；`pnpm gen:api` 后 `pnpm build`（含 vue-tsc）与 `pnpm test` 通过；生成层里不再有接入点与模型目录函数；dev 库真实 HTTP 冒烟通过；浏览器走查：新建提供方（不添模型）→ 编辑添加两个模型 → 保存 → 列表协议与模型正确 → 编辑其中一条模型的描述与标签 → 移除一条 → 切换协议（确认提示、专属字段清空）→ 重名提供方被拒 → 删除提供方 → 访问 `/models` 落到未找到页。

## Out of Scope

- 调用模型的运行时执行链路、Agent 绑定模型。
- 跨提供方按分数路由、故障转移、「提供商侧模型名 / 显示名」分离（已放弃，不预留字段；将来作为新需求重新设计）。
- 提供方级 / 模型级的启用开关；内置提供方预设。
- 连通性测试、从供应商 API 拉取模型清单。
- `ApiKey` 读取侧脱敏与「留空表示不修改」。
- 新增协议及其专属字段。
- 标签的任何改动（标签仍由标签页面维护，本 spec 只消费它的全量列表）。
- 仓库里其它聚合的边界复核；权限体系。
