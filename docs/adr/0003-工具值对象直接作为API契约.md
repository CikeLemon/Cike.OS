# 工具值对象直接作为 API 契约：放在 Domain.Shared，不另建 DTO 镜像

工具的三个值对象（`ToolSetting` 多态族、`ToolParameterDefinition`、`ToolValue`）同时是领域类型、持久化形状和 API 契约形状，不再维护一对一的 `*Dto` 镜像与 `ToolSettingMapper`。为让契约层引用得到，它们放在最稳定的 `Domain.Shared` 层；`Domain.Shared` 为此引用 MCP SDK（`ModelContextProtocol.Core`），`HttpTransportMode` 直接复用 SDK 枚举而不是另造一个。多态判别键 `type` 在 API 与数据库中都是 `ToolType` 的数值；`TimeSpan` 以 System.Text.Json 的 ISO 形状（`"00:00:30"`）传输，前端用「秒」编辑、提交时换算。

## Considered Options

- **契约层维护独立 `ToolSettingDto` 族 + 显式映射器**（此前做法）：API 形状与领域形状解耦，但多出 6 个 DTO、一个映射器和一套「秒」字段，每次改字段要改三处；项目当前只有一套 API 消费方，解耦收益兑现不了。
- **在 `Domain.Shared` 自造 `McpTransportMode` 枚举**：避免 Domain.Shared 引 MCP SDK，但领域里出现两个语义相同的枚举，消费 SDK 时还要映射一次。
- **把值对象改成「秒」整数字段以贴合 API**：让领域为接口让路，反向耦合。

## Consequences

- API 形状与领域形状绑定：改值对象字段 = 破坏性接口变更，需走 `api/v1 → v2` 的版本纪律。
- `Domain.Shared` 从「只有枚举与常量」变为也承载可被契约层复用的值对象，并引用 MCP SDK；后续新增值对象若要直接出 API，须满足：不可变、无领域服务依赖、序列化形状即承诺形状、位于 Domain.Shared。
- 派生属性（如 `ToolValue.IsParameterReference`）需显式 `[JsonIgnore]`，否则会出现在响应里。
- 工具形态（`Tool.Type`）创建后不可变：`UpdateToolDto` 不含 `type`，聚合根在 `Update` 时用现有形态校验设置子类型；要换形态只能删了重建。这样也把「编辑后旧技能目录清理」简化为同形态内比较目录。
- Swashbuckle 不识别 `[JsonPolymorphic]`，多态子类型与判别键在 Swagger 装配处显式声明，并把判别键类型修正为 integer（`ToolSettingDiscriminatorSchemaFilter`）。
- MySQL `json` 列会重排对象成员，System.Text.Json 默认要求判别键在首位；解法是 `JsonHelper.Options.AllowOutOfOrderMetadataProperties = true`（项目统一的 JSON 选项，EF 值转换与 HTTP JSON 共用），不写任何重排逻辑。注意 STJ 只在「声明类型是基类」时才写判别键，序列化多态值对象必须按基类声明。
