# 接入点升为聚合根：三层聚合拆成两个两层聚合

> 2026-11-27：本文已被 [ADR 0007](./0007-模型提供方即连接模型为其子实体.md) 取代——接入点与映射整体删除，不存在三层；「按不变量划聚合边界」的判据本身仍然有效，现行先例是 `ModelProvider → ModelEntity`。

ADR 0005 把接入点做成提供方聚合内的子实体，依据是「接入点归属于提供方」。但聚合边界看的是不变量与事务一致性，不是归属感。重新按三条标准评估：边界内必须有需要事务一致性保证的不变量；聚合尽量小；跨聚合按 Id 引用。提供方与接入点之间**没有任何不变量**——提供方只有名称，接入点之间不去重、提供方可以有零个接入点（都是 0005 自己定下的）。「接入点名称同提供方内唯一」是按提供方 Id 的查询约束，与「提供方名称同租户唯一」同性质，本来就该在用例里查库校验。而三层聚合是仓库首例，代价是实打实的：每写一个接入点都要把整个提供方连同全部接入点与映射（含密钥）加载进内存，还要为它专门写一个两级 Include 的自定义仓储；接入点作为子实体工厂是 `internal` 的，却有全局 Id、被 URL 直接指认、有自己的用例 / DTO / 路由。自 ADR 0005 的接口形态修订（接入点独立增删改查）之后，它在接口上已经是独立资源，却仍在付聚合的代价。决定：**接入点升为聚合根；提供商映射继续做接入点的子实体；三层聚合拆成两个两层聚合。**

## Considered Options

- **保持三层聚合、接入点做子实体**（ADR 0005 的决定）：没有任何跨接入点的不变量需要一致性边界，却要承担整棵加载与自定义仓储的成本；接入点的独立增删改查只能靠「加载整棵、改一个、存整棵」实现。
- **接入点与映射都升为聚合根**：映射没有独立的生命周期与管理入口，而「一个接入点对一个模型只映射一条」必须对着接入点的集合断言，是真不变量，映射应当留在接入点的边界内。
- **接入点升根，但在提供方上保留接入点集合导航**：两个聚合之间保留对象引用会诱导「加载整棵」的写法回潮，按 Id 引用更干净；提供方删除时的连带删除由用例显式完成。
- **接入点有自己的端点类，但保留挂在提供方下的嵌套路径**（`/ModelProviders/{id}/Endpoints/{endpointId}`，每个方法显式指定路由）：聚合根应当对应顶层资源；嵌套路径约定路由表达不了，只能逐个方法手标路径，而且取一条接入点还得带上与它无关的提供方 Id。

## Consequences

- 聚合变为两个两层：`ModelProvider`（租户级聚合根，只有名称）；`ModelProviderEndpoint`（租户级聚合根：所属提供方 Id、名称、协议、接入地址、密钥、协议专属设置、映射集合）→ `ModelProviderMapping`（接入点聚合内的子实体）。
- 不变量的归属：协议创建后不可变、协议专属设置的子类型与协议一致，以及映射按模型整体同步、同一模型只映射一次，由接入点自己的意图方法断言；接入点名称同提供方内唯一、提供方必须存在，由用例查库校验（与提供方名称同租户唯一同一种写法）。
- 两个聚合按 Id 引用：提供方上不再有接入点集合，连带写好的自定义仓储（连同两层子集合加载）一并删除；接入点连同它的映射的加载用通用仓储的一级预加载即可。外键列、索引与删除行为不变；接入点改用聚合根基类后多了一个乐观并发戳列（`ConcurrencyStamp`，与其它聚合根一致），迁移只增这一列。
- 删除语义不变：删接入点连带其映射；删提供方时由用例查出名下全部接入点（连同映射）一并删除；删模型时任一映射还指向它则拒绝。
- 接入点名称同提供方内唯一没有唯一索引支撑（索引非唯一，见 ADR 0001），并发窗口按 ADR 0001 接受，与提供方名称一致。
- 接入点有自己的端点类与约定路由（平铺的顶层资源 `/ModelProviderEndpoints`）：列表按提供方 Id 过滤、单条详情、新建、更新、删除；新建请求体带所属提供方 Id。不再寄宿在提供方的端点类里，也不用显式指定路由。映射仍然没有独立接口。
- 取代 ADR 0005 中「聚合变为三层」「聚合连同两层子集合的加载走自定义仓储」「三层聚合是首例，落地前冒烟验证」三条，以及其 2026-11-27 修订注记里「端点方法放在提供方的端点类里」的接口形态；0005 的其余内容（连接下沉到接入点、映射归接入点、协议不可变、协议专属设置用多态值对象、迁移）不变。
