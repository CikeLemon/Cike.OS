# 模型提供方即连接，模型是其子实体

ADR 0004–0006 把「模型」做成平台级目录，再用接入点与提供商映射把它和供应商连起来，依据是「同一个市面模型要能在多个供应商 / 多条连接之间按分数路由」。参照 zcode 的模型设置重新评估：它只有两层——提供方 = 接入地址 + 协议 + 密钥，模型列表挂在提供方下面，没有「平台模型」这一层，也没有跨提供方路由。路由这个需求在本系统里没有确定的来源，却带来了三层概念、两张额外的表，和一整套只为把它们连起来的维护成本。决定：**删除接入点与提供商映射；模型提供方收敛为一条连接（名称、一种协议、接入地址、密钥、协议专属设置），模型是它聚合内的子实体。同一家供应商有几种协议就建几个提供方。**

## Considered Options

- **保留三层，只在界面上按提供方折叠**：概念与两张表都还在，界面与模型对不上，维护成本不变。
- **模型做独立聚合根、带提供方外键**（访谈中先提出的方案）：模型只有名称 / 描述 / 标签，没有独立于提供方的生命周期与管理入口，随提供方表单一起提交即可；独立出去要多一套用例、端点和 DTO，还要为级联删除保留跨聚合导航。
- **保留平台级模型目录，只去掉接入点（映射直接挂提供方）**：仍要回答「同名模型在不同提供方下是不是同一个」——没有路由，就不需要区分。

## Consequences

- 聚合：`ModelProvider`（租户级聚合根：名称、协议、接入地址、密钥、协议专属设置）→ `ModelEntity`（聚合内子实体：名称、描述、标签引用，随提供方的表单整体同步，没有独立接口）。
- 模型只有名称一个名字，创建后不可变，同一提供方内不重复（聚合内部不变量，在同步时断言，前提是集合已加载）；不同提供方可以重名，且是互不相干的条目。标签仍是平台级目录，模型以 Id 引用。
- 协议可修改。ADR 0005 定为不可变时，「删提供方重建」的代价只是一条连接；现在重建会丢掉名下全部模型。更新时协议专属设置的子类型必须与新协议一致——这是对输入的字段校验，放 FluentValidation，不在聚合里断言。
- 放弃的能力：按分数在多个提供方之间路由、故障转移、提供商侧模型名与显示名分离。将来需要时作为新需求重新设计，不预留字段。
- 数据：删除接入点与映射两张表；模型加回租户与所属提供方、去掉显示名称与并发戳。dev 库旧数据清空，不写数据迁移。
- 取代 ADR 0004（模型目录平台化）、0005（接入点与协议）、0006（接入点升为聚合根）。`Backend/AGENTS.md` 中以接入点 / 映射为先例的条款改为 `ModelProvider → ModelEntity`。
