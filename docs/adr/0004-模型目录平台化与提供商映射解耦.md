# 模型目录平台化与提供商映射解耦

> 修订：连接设置下沉为「接入点」、映射归接入点，见 ADR 0005。本文中「ModelProviders 表结构不变」「映射是提供方的子实体」「一个提供方对一个模型只映射一次」「映射在提供方表单里维护」四条已被取代；模型目录平台化部分仍然有效。

模型不再是挂在模型提供方下的条目，而是**平台级目录实体**（无租户）：`Name`（模型名称，如 glm-5.3，创建后不可变）+ `DisplayName`（显示名称）+ `Description`（可选）+ `TagIds`，全局唯一地定义市面上的模型本身。

「谁提供这个模型」归到模型提供方一侧：**提供商映射（ModelProviderMapping）是 `ModelProvider` 聚合内部的子实体**，记录提供方接入了哪个模型、路由分数 `Priority`、提供商侧模型名 `ProviderModelName`（非空字符串列，空字符串表示回落用模型 `Name`）。映射随提供方整体维护，没有独立的用例、端点与界面入口。调用某个模型时，在同租户各提供方的映射里取分数最高的，用其提供方的连接设置与提供商侧模型名发请求。

## Considered Options

- **保持原结构（模型挂 ModelProviderId），视图层按名称去重展示**：「同名即同一模型」的判断埋在查询或前端，路由语义（分数、提供商侧模型名）没有落库的位置；且原 Models 表无任何唯一索引，同名重复条目本来就是合法数据。
- **模型上指定默认映射，其余做备胎**：failover 依赖人工切换，映射的字段一个都少不了，只是把路由规则从「取最高分」弱化成「手动挑一个」。
- **模型聚合持有映射子集合**：模型平台级、映射租户级，聚合加载不能跨租户边界持有子集合，结构上不成立。
- **映射作为独立聚合根（独立用例与增删改查接口）**：映射只有一个生命周期主人——提供方；独立出去要多养一套用例、端点和前端对话框，还把「映射」这个运维概念推到了模型侧界面上。

## Consequences

- 引入系统内**第一批非租户实体**（Model、Tag 去掉 `IMultiTenant`）。平台目录现阶段由现有管理端直接维护、不做权限区分；权限收口推迟到权限体系提案。
- 数据迁移：Models 表去掉 TenantId / ModelProviderId、新增 Description；Tag 去掉 TenantId；新增 ModelProviderMappings 表（外键指向 ModelProviders，随聚合级联软删）；ModelProviders 表结构不变。
- 映射只能经 `ModelProvider.SyncMappings(...)` 整体同步（以模型为键：已映射的更新、新的新增、未提交的移除）；对外只有提供方的增删改查，映射内嵌在提供方 DTO 里进出。
- 唯一性 / 存在性：模型 `Name` 全局唯一、`DisplayName` 全局唯一（Handler 查库）；提供方名称同租户唯一（Handler 查库）；**一个提供方对一个模型只映射一条**是聚合内部不变量，在 `SyncMappings` 里断言，不需要查库；映射引用的模型必须存在（Handler 查库）。`Priority` 只是排序分数，**不做唯一**。`ProviderModelName` 为非空字符串列（不用 null），长度 ≤ 128。
- 删除语义：删提供方时名下映射随聚合一并删除；删模型时任一租户还有映射指向它则拒绝。
- 前端：模型列表 / 详情只展示目录本身，不出现映射；映射在「模型提供方」的表单里维护（每行：模型、分数、提供商侧模型名）。
- 分数是人工静态路由规则；未来按输出内容的点赞/踩与评测分数自动选路时，以映射为分析与叠加单元，本决策不预置其字段。
