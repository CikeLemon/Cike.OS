# 模型目录平台化与提供商绑定解耦

模型不再是挂在模型提供方下的条目，而是**平台级目录实体**（无租户）：`Name`（技术名，如 glm-5.3）+ `DisplayName` + `Description` + `TagIds`，全局唯一地定义市面上的模型本身。模型提供方维持租户级聚合不变（连接设置）。两者之间新增租户级独立聚合根 **模型绑定（ModelBinding）**：`ModelProviderId` + `ModelId` + `Priority` + 可空的 `ProviderModelName`（提供商侧模型名，空时回落用模型 `Name`）。调用某个模型时，取该模型下同租户优先级最高的绑定，用其提供商的连接设置与提供商侧模型名发请求。

## Considered Options

- **保持原结构（模型挂 ModelProviderId），视图层按名称去重展示**：「同名即同一模型」的判断埋在查询或前端，路由语义（优先级、提供商侧模型名）没有落库的位置；且原 Models 表无任何唯一索引，同名重复条目本来就是合法数据。
- **模型上指定默认绑定，其余做备胎**：failover 依赖人工切换，绑定的字段一个都少不了，只是把路由规则从「取最高优先级」弱化成「手动挑一个」。
- **模型聚合持有绑定子集合**：模型平台级、绑定租户级，聚合加载不能跨租户边界持有子集合，结构上不成立。
- **绑定作为 ModelProvider 聚合的子集合**：绑定有两个生命周期主人（删模型看绑定、删提供商也看绑定），塞进提供商聚合后模型侧用例要跨聚合改别人的子实体。

## Consequences

- 引入系统内**第一批非租户实体**（Model、Tag 去掉 `IMultiTenant`）。平台目录现阶段由现有管理端直接维护、不做权限区分；权限收口推迟到权限体系提案。
- 数据迁移：Models 表去掉 TenantId / ModelProviderId、新增 Description；Tag 去掉 TenantId；新增 ModelBindings 表；ModelProviders 不变。
- 唯一性校验（均在 Handler 做）：模型 `Name` 全局唯一；模型 `DisplayName` 全局唯一；提供商名称同租户唯一；绑定（租户 × 模型 × 提供商）唯一；绑定优先级同模型同租户唯一（保证「取最高优先级」无歧义）；`ProviderModelName` 可空、非空时长度 ≤ 128、不做唯一性。
- 删除语义：删模型存在任一绑定则拒绝；删提供商级联软删其全部绑定；删绑定直接删。
- 前端侧栏从「模型」单菜单拆为「模型」与「模型提供方」两个一级菜单；对话/Agent 侧的模型选择器只查目录表即可展示，不再依赖提供商维度。
- 优先级是人工静态路由规则；未来按输出内容的点赞/踩与评测分数自动选路时，以绑定为分析与叠加单元，本决策不预置其字段。
