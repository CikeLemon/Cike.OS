# 插件作为工具的分发单位，且插件不包含 Agent

技能、MCP 服务、OpenAPI 服务常需成组交付（技能的指令隐含依赖同组的 MCP/OpenAPI 可用），分开上架、分开安装会导致组内不一致，因此以插件（1..N 个工具）作为上架与安装的唯一单位，工具不独立上架。与 Claude Code 插件不同，插件不包含 Agent：Agent 面向最终使用者、插件面向 Agent 搭建者，受众、审核与权限不同，故拆为 Agent 市场与插件市场两个市场，二者通过「Agent 挂载插件」关联。由于插件暂无版本、工具可随时增减，Agent 挂载整个插件而非单个工具，避免「插件新增工具何时同步到 Agent」的问题；代价是插件内无法收窄权限，需靠作者按权限边界拆分插件。

## Considered Options

- 工具独立上架：粒度过细，成组能力的一致性无法保证。
- 插件内含 Agent（Claude Code 模式）：单一市场更简单，但混淆了两类受众的浏览、审核与授权边界。
- Agent 挂载单个工具：权限更细，但在无版本前提下插件工具增减无法确定同步时机。
